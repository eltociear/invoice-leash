# AI usage

Invoice Leash was built by one person working with an AI coding agent, and it is *about* AI agents.
This file covers both: how AI was used to build it, what the AI produced, what the human did, how
the AI's work was checked, and the mistakes the AI made that those checks caught.

## Summary

| | |
|---|---|
| **AI** | Claude Code (Anthropic), model `claude-opus-5-5`: one main session that writes code, runs the testnet steps and reports, plus sub-agents started for independent reviews and research |
| **Human** | the team (one person, [@eltociear](https://github.com/eltociear)): goals, product decisions, accounts and wallets, everything that needs a human identity, and the final call on what ships |
| **Written by the AI** | nearly all code, tests, scripts, documentation, the demo video (slides, narration script, music) and the cover image |
| **How the AI's work is checked** | not by trusting it: `npm run verify` (94 read-only checks against the live testnet), 59 Foundry tests and 5 invariants, a 14-mutant check, Slither, QoreScan, browser tests, CI daily, and AI reviewers that did not write the code |

## The workflow

1. **The human sets the goal and the constraints.** For example: "enter the Post-Quantum AI Agents
   track"; "make the agent pay in fUSD"; "build an interactive web demo, but with no server";
   "add Foundry tests and use QoreScan and QoreChain's MCP server"; "review everything for problems";
   "look at the other projects and find what to strengthen".
2. **The AI reads the sources first.** It reads the `@qorechain/sdk` type definitions and bundled code,
   the workshop example, the hackathon rules, FAQ and rubric, and the other entries' public repositories.
   Where the SDK and the chain disagreed with the docs, it went by the chain.
3. **The AI builds and runs it against the live testnet.** It wrote the contracts, the CLI, the agent and
   the MCP server, deployed to `qorechain-diana`, and recorded every run as JSON with transaction hashes
   (`runs/`).
4. **The AI probes its own claims.** When a claim could be tested on chain, it was. The v1 claim "the
   agent can only call `pay`" was tested with probe transactions and turned out false (a spending rule
   bounds amounts, not destinations, see the README). That probe led to the v2 redesign: the agent got its
   own account that can move nothing.
5. **Independent review by AI agents that did not write the code.** For the full review, three
   sub-agents read the repository in parallel, with no access to the main session's reasoning: one for
   the contracts and tests, one for documentation claims against recorded evidence, and one for scripts
   that would break over time. A fourth read other public entries in the track, to see what was already common. Their findings were checked, then
   fixed or documented (below).
6. **Machine checks, then CI.** Every change runs `npm test`, `forge test` and `npm run verify`. CI
   re-runs everything daily against the live chain, so a claim that stops being true turns the badge red.
7. **The human decides what ships,** reads the summaries, and does what needs a person: wallets,
   uploads, the project form.

## What the human did

- Chose the hackathon, the track and the goal, and kept raising the bar ("think deeply", "review
  everything", "find more to strengthen").
- Made the product decisions when asked: the name (after two other entries were already called *Leash*),
  a server-less web demo, Foundry tests, QoreScan and QoreChain's MCP server, fUSD payments, redoing the
  video for v2, doing every improvement found in the reviews.
- Did what needs a person: registration and the QoreX wallet (the AI never saw its keys or recovery
  phrase), faucet claims, uploading the videos to YouTube, and filling in the project page.
- Reviewed the results as they came in, and decided what to publish.

## Checking the AI, not trusting it

| What the AI claims | What checks it |
|---|---|
| "the deployed contract is this source" | `verify` recompiles and compares bytecode |
| "the chain refused this attack" | `verify` re-reads every recorded transaction and its failure event |
| "the contract enforces X" | 59 Foundry tests, 5 invariants (256,000 random calls), 14 of 14 mutants caught |
| "the only signature scheme is ML-DSA-87" | QoreScan CBOM, re-run by `verify` |
| "the page works" | `npm test` parses every page script; Playwright runs the lab in a real browser |
| "the docs say N" | `npm test` checks every stated count against its source; `verify` fails when its own count drifts |
| "the MCP agent did X" | the server's log is audited independently against the chain with `@qorechain/mcp` |

## Mistakes the AI made, and what caught them

Listed because they show why the checks exist.

- **An overclaim in its own design (v1).** The README said the agent could only call `pay`. The AI's
  own probes showed a rule-bound key could still send QOR, or transfer a listed token anywhere. Fix: the
  v2 redesign, and the finding published with transaction links.
- **Docs that overstated.** "The agent's account holds nothing" (it held 0.64 QOR for fees) and "its
  rule lists no real denom" (it lists fBTC, capped at 1 satoshi). Caught by the docs-versus-evidence
  reviewer. Fix: precise wording.
- **A broken live page.** One apostrophe inside a template literal broke the attack lab's script for
  several hours. Caught while adding a feature to the lab. Fix: `npm test` now parses every page script,
  and the test was confirmed to catch the old bug.
- **Checks that would fail by themselves.** A `verify` expectation that would turn red when the demo
  invoices fell due, and a check that anyone could break by sending Mallory 1 uqor. Caught by the
  scripts reviewer. Fix: expectations derived from chain state; griefing-proof checks.
- **A tool restriction that did not hold.** The first read-only audit run used a shell tool it had not
  been granted, because of the local permission mode. Fix: the run was redone with every other tool
  explicitly disallowed, and `verify` now checks the audit's tool list.
- **A test that proved less than its name.** The "UTC day reset" test passed with a rolling 24-hour
  window too. Caught by the contracts reviewer. Fix: it now pays at 23:59:59 and again at 00:00:00.
- **A test gap.** The mutation check missed "vendor key algorithm not checked" on v2. Fix: new tests;
  14 of 14 mutants are now caught.
- **A misread fuzzer failure.** The first invariant run failed. The AI traced it to the test harness (the
  fuzzer could call a setup function, and one fixture is genuine on the desk under test), not the contract.
- **A stale number in a document.** After `verify` grew, this file still gave its old count (82). Fix:
  `test/docs.test.mjs` checks every count the documents state against its source (and catches this one).
- **A regression from a security fix.** Scoping the company's windows to one target broke `deploy-v2`: it
  named the desk's address before the desk existed. Caught by an AI reviewer that tried to set the project
  up from scratch. Fix: the deploy gets its own one-transaction window. `desk.mjs setup` was then run end
  to end on the testnet.
- **Tools that misreported.** An independent audit found that the MCP server showed the model an unsigned
  amount label, accepted any registered signer as "authentic", and could report a payment whose answer was
  lost as refused. Fix: the signed amount only, the company's signature only, an OUTCOME UNKNOWN state
  settled by `paid()`, and `test/agent.test.mjs`. The setup run then found two more of the same kind (a
  network error shown as a refusal, a 404 shown as an error), now fixed.
- **Numbers stated wrong in conversation** (17 attempts for 16, 11 mutants for 10). The human was given
  the corrected numbers; the README's numbers come from `verify`.
- **Local metadata in a published log.** An early Claude Code stream log included local paths; it was
  sanitized in a later commit (the earlier commit still has it).

## AI inside the product

- **Claude as the decider.** `node leash.mjs run --llm` (v1) lets Claude read the inbox and choose
  actions. The same inbox also runs with a compromised decider that obeys every instruction. The project's
  claim is that what the agent *can* do does not depend on the model. v1: Claude made 5 attempts and 2
  were refused; the compromised decider made 11 and 8 were refused.
- **Claude Code through MCP.** `runs/mcp-v2-claude-final.txt`: Claude Code, with nothing but the
  invoice-leash MCP server, dry-ran all nine invoices and paid the three genuine ones (220 fUSD).
  `runs/mcp-v2-compromised-final.txt`: an obey-everything client with the same tools was refused 12 times.
- **Claude Code on a sealed inbox.** `runs/mcp-v2-sealed-final.txt`: the two invoices arrived as ML-KEM-1024
  envelopes; the server opened them; Claude paid the genuine one (20 fUSD) and refused the sealed forgery.
- **Claude Code as auditor.** `runs/mcp-v2-audit-final.txt`: given read-only tools and QoreChain's own
  MCP server, and told not to trust the agent's server, it matched all 15 transactions on chain.
