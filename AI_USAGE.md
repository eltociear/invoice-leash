# AI usage

## In the product

`node leash.mjs run --llm` (v1) uses Claude as the agent's decider: it reads the inbox and returns a
plan of `pay` / `send` / `call` / `skip` actions. The project's claim is that what the agent can do
does not depend on the model, so the same inbox is also run with a deliberately compromised decider
that obeys every instruction: it tries more, and the chain refuses more, but both are bounded by the
same rules (v1: Claude 5 attempts, 2 refused; compromised 11 attempts, 8 refused).

`mcp/server.mjs` exposes the same agent as MCP tools; `runs/mcp-v2-claude-final.txt` (v2, fUSD) and
`runs/mcp-claude-final.txt` (v1) are Claude Code (claude-opus-5-5) using them, with nothing but that
server; `runs/mcp-v2-audit-final.txt` and `runs/mcp-audit-final.txt` are Claude Code auditing those
actions with read-only tools only, through QoreChain's own MCP server.

## In building it

This project was built with Claude Code (Anthropic) as a coding assistant: reading the QoreChain
SDK typings and the workshop example, drafting the contract, the CLI and this documentation, and
running the testnet steps. The design (moving every limit out of the agent; in v1 scoping the
agent to the `pay` selector, in v2 giving it its own account after our probes showed the v1 scope
was not enough; checking invoice signatures before the replay guard) and every result in `runs/` were checked against the live
`qorechain-diana` testnet, not taken from the model's word. `npm run verify` re-does that check
for anyone, and CI runs it daily.

The demo video's narration is synthesized with [Kokoro](https://github.com/hexgrad/kokoro)
(Apache-2.0, voice `af_heart`); its background music is generated by a script, not sampled.
